# Backend System Overview

This document provides an overview of the backend architecture and components for the Carelink system.

## 1. Overview
The backend of Carelink is designed to support a multi-platform application (mobile, web, admin dashboard) for healthcare-related services. It leverages Firebase as the primary backend-as-a-service (BaaS) provider, with custom serverless functions and integrations for business logic, notifications, and data management.

## 2. Core Technologies
- **Firebase Firestore**: NoSQL cloud database for storing user data, bids, jobs, and other entities.
- **Firebase Authentication**: Handles user sign-up, sign-in, and authentication flows.
- **Firebase Cloud Functions**: Serverless backend logic for handling events, notifications, payments, and custom workflows.
- **Firebase Cloud Messaging**: Push notifications to users and admins.
- **Firebase Storage**: Stores user-uploaded files and media.
- **Admin Dashboard**: Built with Next.js, connects to Firebase for admin operations.

## 3. Key Backend Components
### a. Firestore Database
- **Collections**: Users, Jobs, Bids, Notifications, Payments, etc.
- **Security Rules**: Enforced via `firestore.rules` to protect data access.

### b. Cloud Functions
- **Location**: `functions/` and `admin-dashboard/functions/`
- **Purpose**: Handle business logic such as bid expiration, job notifications, payouts, refunds, and verification.
- **Examples**:
  - `payout_functions.js`: Handles payment disbursements.
  - `refund_functions.js`: Manages refunds for failed/cancelled jobs.
  - `index.js`: Entry point for function exports.

### c. Authentication
- **User Management**: Email/password, social logins, and admin roles.
- **Custom Claims**: Used for role-based access in the app and dashboard.

### d. Notifications
- **Push Notifications**: Sent via Cloud Messaging for job updates, bid status, and system alerts.
- **Admin Alerts**: Special notifications for admin users.

### e. Admin Dashboard
- **Tech Stack**: Next.js (React), connects to Firebase via SDK and REST APIs.
- **Features**: User management, job monitoring, payout/refund management, system configuration.

## 4. Security
- **Firestore Rules**: Restrict access based on authentication and user roles.
- **Function Permissions**: Functions are protected and only callable by authorized users or triggers.
- **Environment Files**: Sensitive keys (e.g., `firebase-admin-key.json`) are secured and not exposed to clients.

## 5. Deployment & Hosting
- **Firebase Hosting**: For web and admin dashboard frontends.
- **Cloud Functions**: Deployed via Firebase CLI.
- **App Hosting**: Defined in `apphosting.yaml` for admin dashboard.

## 6. Extensibility
- **Modular Functions**: New business logic can be added as new Cloud Functions.
- **Scalable Database**: Firestore supports scaling as user base grows.
